## 9. Limitations

- **Diagnostic, not acceptance.** A passing comparison only shows that both sides could be captured; fidelity is judged from the evidence (§11).
- **Invented data in stories, the browser tests' data and Spree's sample catalog on screens.** Names, counts and records differ on purpose.
- **Seeded data.** The extra price lists, catalogs, collection, category, import, role and teammates were added to the browser-test database through the Admin API. They exist only in that database, which is local and discarded, and Spree's tests and fixtures are unchanged. Spree's sample data stops before its sample orders, as in part 1, so no screen shows a product's orders; part 2's screens do not need them.
- **States reached by answering a request** show how the screen renders that answer, not that the server would send it (§2.1).
- **FL-21 ran once,** for one file, one export with no filter, as the admin, on one machine, with the background jobs running inside the server as the browser tests run them. How long a job takes on a production server is not measured.
- **The emails use the fallback font,** because their web font is not fetched (§2.4).
- **Spree's specs ran on SQLite, locally.** CI runs Spree's suites on PostgreSQL and MySQL, and two examples run on PostgreSQL only.
- **Size.** Part 2's 612 reference images are 16.8 MB, and its evidence is 21 MB. The evidence images are lossless WebP.
- **Reference images from one machine.** The reference images were made in the pinned image on this session's machine. One story's dark image varies between runs there (§8).
- **Not independent.** The session that built the stories also compared them. Under the owner's delegation of 2026-11-04 the routine acceptance is also made by an automated session, recorded as delegated acceptance (§11).
