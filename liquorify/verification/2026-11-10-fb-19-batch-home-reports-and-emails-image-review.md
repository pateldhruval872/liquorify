**What to look at.** Each link opens the image beside this list, in the revision being read, and the pull request's file list shows the same images. Every image was looked at in light and dark before it was committed. No story was corrected after it was first written.

Stories use invented shops, products, people, addresses and references. The running screens show the browser tests' own records and the orders, saved reports and staff the batch's scripts added on the browser-test server, and Spree's seeds and sample data on the emails gem's test app.

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on Spree's running admin dashboard, and the result is in the [verification record](2026-11-10-fb-19-batch-home-reports-and-emails.md) §4. Images and computed styles are in the [evidence index](evidence/2026-11-10-fb-19-batch-home-reports-and-emails/README.md). The comparison is diagnostic: it informs the review and does not decide it.
- **Seen in a capture:** the state appears in a running-screen capture, or in a flow script's images, linked here, but the script did not put the story beside it. A capture of a role other than the admin names the role.
- **Not compared; checked against its source:** no running screen showed that state with the test data, or the script could not reach it there, so it was checked against the component's source only, with the reason. These stories, with the ones seen in a capture, are G-101 (record §7).

**How a decision is recorded.** An image is accepted or rejected in the pull request, row by row or as a whole. An image rejected is fixed in its story, its providers or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).
