# FB-19 storefront shop batch, part 1, reference images for the owner's review

The owner accepted every image on 2026-10-30, with the screen evidence and fidelity, within the limits the [verification record](2026-10-26-fb-19-batch-storefront-shop-part-1.md#11-the-owners-review-2026-10-30) gives, after storefront #20 at `da06743` and #21 at `8864f60` merged on 2026-10-27, so the Owner column reads ACCEPTED. The hero, the pilot's story that part 1 compared again, was accepted on part 2's corrected comparison at 390 pixels, and the mobile menu's focus outline, drawn in its stories and not on the running screen, is explained in the same section.

**What to look at.** Each link opens the image as committed on storefront pull request [#20](https://github.com/pateldhruval872/liquorify-storefront/pull/20), at `da06743`; the pull request's file list shows the same images. Each story has two: `mobile` at 390 pixels and `desktop` at 1280. The storefront shows no dark mode, so there is one theme. Every image was looked at before it was committed.

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on the running storefront, and the result is in the [verification record](2026-10-26-fb-19-batch-storefront-shop-part-1.md) §4. "Compared within" means the component was compared as part of a larger one that holds it. Images and computed styles are in the [evidence index](evidence/2026-10-26-fb-19-batch-storefront-shop-part-1/README.md). The comparison is diagnostic: it informs the owner's review and does not replace it.
- **Seen in a capture:** the state appears in a running-screen capture, linked here at 1280 pixels (390 for the menu's control, which shows only there), but the script did not put the story beside it. The owner can look at both.
- **Not compared; checked against its source:** no running screen showed that state with the data, so it was checked against the component's source only. The reason is given.

**How a decision is recorded.** The owner accepts or rejects in the pull request, row by row or as a whole. An image rejected is fixed in its story, its fixtures or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).
