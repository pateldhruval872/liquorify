## 3. Procedure and evidence for each criterion

**1. Builds.** Each workflow builds the Storybook from a clean checkout with a frozen lockfile. The backend first builds the Admin and Seller SDKs, which the stories import from their built files. Every run above built.

**2. Token check and coverage.** Each run's "Check token files" step regenerated the token files from the stylesheets (and, in the backend, the ID list from LIQ-009) and found no difference. The coverage report ran and wrote the tables in §1 to each run's summary page. It found no tag that names an unknown ID.

**3. Pinned environment.** The reference images were made in this session in the same pinned images, run through Docker (`pnpm visual:update`), and committed. Run 39624846976 and run 39628713735 then compared them on GitHub's runners with Playwright's default colour tolerance and no pixel allowed beyond it, and all matched. Before committing, the backend's check was run three times and the storefront's twice in this session, with identical results each time.

**4. Deterministic data.**
- Fixtures are invented. `src/fixtures/fixtures.test.ts` (backend) and `stories/fixtures/fixtures.test.ts` (storefront) parse them with the SDKs' own schemas; both pass in each repository's unit test job.
- The clock is fixed at `2026-10-01T12:00:00Z`, the locale is `en-US` and the time zone is UTC.
- The test aborts every request that leaves the local Storybook server and fails if there was one. None did in any run.

**5. Same revision twice.** Backend run 39628676562 and storefront run 39628713735 were each re-run once, unchanged. Each attempt passed, which with the strict comparison means each produced the committed images exactly. Backend `21c9885` and `f873bfd` differ only in two scripts that take no screenshots, so run 39624846976 is a third matching run.

**6. Planted change.** A throwaway draft pull request in each repository ([#7](https://github.com/pateldhruval872/liquorify/pull/7), [storefront #16](https://github.com/pateldhruval872/liquorify-storefront/pull/16)) changed the button's Default story label and added a story with no reference image. In each run:
- the changed story failed in both of its modes, with the reference, actual and difference images in the log;
- the new story failed in both modes with "No reference image yet", and a proposed image was attached;
- every other story passed;
- no reference image was written, and the workflow's token can only read the repository, so it could not commit one;
- `visual-report` (13 files) and `visual-failures` (14 files) were published, both expiring on 2026-11-04, 14 days later.

Both pull requests were closed without merging. Their branches could not be deleted from this session (the push was refused), so they remain until someone deletes them. The failure artifact could not be downloaded here either, because this session's network policy refuses GitHub's artifact storage host. So `pnpm visual:copy` was tried on a local folder rebuilt from the file paths the run's log names, 14 files in the same layout: it copied exactly the four images a reviewer would accept (the two actual images of the changed story and the two proposed images) and skipped the expected and difference images, the attachment copies and the error notes.

**7. Advisory.** The rulesets require 15 named checks in the backend and `Lint`, `Type Check` and `Unit Tests` in the storefront ([FB-02 record](2026-10-21-fb-02-merge-push-and-protection.md)). Neither list includes "Storybook & visual check", and this work did not change the rulesets. Storefront pull request #15 reports `unstable`, not `blocked`, while its advisory E2E job fails for the missing Stripe keys (OA-1).

**8. What is added.** `git diff` against each base:
- Backend: `packages/liquorify-storybook/` (129 files), `.github/workflows/storybook.yml`, `pnpm-lock.yaml` and LIQ-009. The lockfile change only adds packages and marks one existing package optional.
- Storefront: `.storybook/`, `stories/`, `visual/`, `.github/workflows/storybook.yml`, and `.gitignore`, `biome.json`, `vitest.config.ts`, `package.json` and `pnpm-lock.yaml`. `package.json` gains scripts and three development dependencies (`@storybook/nextjs-vite` and `storybook` 10.6.2, `vite` 8.0.16), and the lockfile has no local path.

**9. Fidelity.** Each image was looked at in this session and matches what the component's source and stylesheet describe. That is not the comparison [LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch) asks for, which needs the component in its running screen.

**10. Review.** The owner reviews the images in pull requests #6 and #15.

## 6. Limitations

- **Automated, not independent.** The same session wrote LIQ-010, built the pilot and ran these checks.
- **Small batch.** Eleven components and the token pages. Interactions the pilot did not reach (forms, the store provider, read-only permissions, server components that fetch data) are tried by the first batch that needs them.
- **Fidelity not checked against running screens** (criterion 9).
- **The failure artifact was not downloaded** (criterion 6); the copy script was tried on a rebuilt folder of the same layout.
- **One browser.** Chromium only, by design ([LIQ-010 §11.1](../LIQ-010-design-system-reproduction-architecture.md#111-environment)).
