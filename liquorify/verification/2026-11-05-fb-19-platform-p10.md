## 4. Nothing leaks (criterion 9)

- Tokens, keys, codes, cookies and passwords stay in the scripts' memory. The browser-test data's admin password is read at run time from the file the browser tests' own setup writes. `storefront-run.mjs` passes the store's publishable key to the storefront in its settings at build and start, and writes it nowhere.
- The passwords of the customers each run adds are fixed in the script, as P7's are. They belong to accounts on a test database that is thrown away when the server stops.
- The results keep statuses, codes, permission keys, whether each check passed and the masked request; never an answer, a token, a code or a known value. The expected action results kept are the storefront's refusal shape (`{ success: false }`), `null`, the run's product names, and two cart ids from the thrown-away database, which open nothing without the cart's token.
- The run logs are kept as `.txt` files, with this machine's folder replaced by `<repository>`. A search of both runs' evidence found no key, token, password or machine path.
