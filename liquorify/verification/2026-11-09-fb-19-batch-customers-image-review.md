# FB-19 batch 10, customers in the dashboard, reference images for review

This list holds every reference image batch 10 commits, by inventory ID ([LIQ-009](../LIQ-009-spree-component-and-token-inventory.md)), so each can be accepted or rejected, the six earlier stories its running screens compare, and the earlier images its fixture correction changed. The batch is accepted by delegated acceptance, under the owner's delegation of 2026-11-04 ([record](2026-11-04-delegated-acceptance-and-merging.md)), by Claude in the thread "Build dashboard customers (batch 10)" ([verification record §13](2026-11-09-fb-19-batch-customers.md#13-delegated-acceptance)). The owner does not review these images. The Acceptance column reads DELEGATED ACCEPTANCE for each.

**What to look at.** Each link opens the image beside this list, in the revision being read, and the pull request's file list shows the same images. Every image was looked at in light and dark before it was committed. Eight stories were corrected after they were first written (verification record §4.3):
- **Customer tax identifiers card: Number refused** (S74) and **Tax identifiers card: Refused, on the field** (S78) drew the regime's wording, "does not look like a valid EU VAT registration", where the running server's answer makes the sheet show "is invalid" (SD-46). Their mocks now answer as the server does, and their images were written again: only the message changed.
- **Customer groups card: Refused for a read-only role** (S35) drew "You are not authorized to access this page." where the server answers "Missing permission: write_customers". Its mock now answers in the server's words, and its images were written again: only the message changed.
- **Customer privacy card: Export refused** (S55) answers with the server's refusal, "Missing permission: read_payments"; its toast reads as before.
- **Customer addresses card: Three addresses, with defaults** (S23), **One address, default for both** (S24) and the address book row's stories drew "Portland, 97209" without the state the server writes. The shared address builder now carries it, and every image it touched was written again: only ", OR" in the address line changed. The same change touched earlier batches' images, listed below.
- The refusal stories, S35, S61, S74 and S78, take focus off after the refusal, so their images do not depend on how fast the refusal comes back.

Stories use invented shops, people, addresses, phone numbers and registration numbers; the running screens show Spree's sample customers, the browser tests' data and the customers the batch added through the Admin API.

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on Spree's running admin dashboard, and the result is in the [verification record](2026-11-09-fb-19-batch-customers.md) §4. Images and computed styles are in the [evidence index](evidence/2026-11-09-fb-19-batch-customers/README.md). The comparison is diagnostic: it informs the review and does not decide it.
- **Seen in a capture:** the state appears in a running-screen capture, linked here, but the script did not put the story beside it. A capture of a role other than the admin names the role.
- **Not compared; checked against its source:** no running screen showed that state with the browser-test data, or the script could not reach it there, so it was checked against the component's source only. These stories, with the ones seen in a capture, are G-96 (record §7).

**How a decision is recorded.** An image is accepted or rejected in the pull request, row by row or as a whole. An image rejected is fixed in its story, its providers or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).
