### 1.1 Changes after the development trials

No expected answer was corrected. Two changes to how a request was sent or judged, which change no expected answer:

- **1.5 sends the discount's `amount`.** The first trial sent a new `value`, which Spree takes only when a discount is created; a change takes `amount` (`Orders::DiscountsController`'s request parameters), so the allowed write changed nothing and its read-back failed. The row now sends a different amount of the same sign. Both refusals were answered as written in that trial too.
- **2.9's read-back reads the consignment's `status`.** The first trial read a field the consignment does not have, so the read-back could not see the allowed change. It now reads `status` and `delivered_at`.

### 2.3 Observations, not cases

Sent after the cases and recorded without judging, as the work item set out. The same answers in both runs:

| Request | Caller | Answer | What it means |
|---|---|---|---|
| Add a payment (row 1.10) | Order manager | 404 `record_not_found` | Spree finds the payment method among those the caller may read, which are settings; the order manager template holds `write_payments` but not `read_settings` |
| Create a fulfilment for waiting units (row 2.1) | Order manager | 404 `record_not_found` | Spree finds the stock location among those the caller may read, which are stock; the template holds neither `read_stock` nor `read_settings` |
| Mark a fulfilment as fulfilled | Packer | 403 `access_denied`, no permission named | A fulfilment's writes need a change to the order (`Orders::BaseController#authorize_order_access!`), which `read_orders` does not allow. No permission is named because the packer holds `write_fulfillments`, the key the gate reads |
| Add tracking | Packer | 403 `access_denied` `write_orders` | Consignments are gated on the order's key, not `write_fulfillments` |

Part 1's and part 2's §3.1 show these controls to these roles: the order manager sees the payments card's Add and every after-sale control, and "Mark as fulfilled is the packer's to use". The server refuses each. None is a refusal answered wrongly, so none is a security finding, and none fails a P12 case. Whether each is a defect, a role template to change or the intended boundary is for the owner; no gap's status depends on them. The owner answered on 2026-11-10, in §2.4.
