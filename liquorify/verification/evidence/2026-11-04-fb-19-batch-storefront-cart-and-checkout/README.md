# FB-19 batch 9, storefront cart and checkout: evidence

The captures, comparisons and results behind the [verification record](../../2026-11-04-fb-19-batch-storefront-cart-and-checkout.md). They come from the storefront's scripts in `visual/fidelity/` (`checkout-screens.spec.ts`, `checkout-settings.spec.ts`, `compare.spec.ts` and `mail.spec.ts`), from Spree's own specs, from Spree's order mailer preview and from the storefront's own unit and browser tests. A successful run of the scripts only shows that each state could be reached and captured. Whether the storefront behaves as it should in each state is recorded in the record's §2 and §8, and fidelity is the reviewer's judgement, here under the owner's delegation.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | Storefront pull request [#24](https://github.com/pateldhruval872/liquorify-storefront/pull/24), branch `claude/project-thread-oie490`, from `main` at `8865498`. The scripts as committed are the ones that produced this evidence, apart from two changes made after a run that the record §13 describes: the code captures wait for a refusal or a removal before reading the page, and were run again with that change; and the manual capture step puts the store's setting back even when it fails |
| Running screens, the browser tests and the order confirmation email | The storefront at `main` `8865498`, which the batch does not change, built for production, against this lane's own browser-test Rails server, with Spree's code at backend `06ccfbce`. EM-SF-01 came from a second storefront and a second browser-test server, from the same build and code, started on other ports so the running servers were left alone: the storefront with a webhook signing secret, the server allowed to reach it (record §7) |
| Dashboard captures | The dashboard built from Spree's code at `06ccfbce`, against the same server. The `revision` in their notes names both, since the storefront's script drove them |
| Spree's specs and EM-C-01 | Spree's code at `06ccfbce` |
| Browser | The storefront's pinned Playwright 1.60.0 image, at 390 and 1280 pixels wide, with the fonts served offline |

**How states were reached.** Most captures are the storefront as built, driven as a shopper drives it. Some states hold, fail or delay one of the storefront's requests in the browser, which the capture's note says; those are simulated interface states (record §2.1, G-74). The settings were saved through the dashboard's own screens in the same runs (`checkout-settings.spec.ts`), each put back afterwards.

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image, 218 in all, was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in the storefront's `visual/__screenshots__/`.

**Data.** The screens show Spree's sample catalog in this lane's own browser-test database, with what the scripts added: a promotion with the code WELCOME10, two gift cards (FIDELITY-PART-25 and FIDELITY-WHOLE-500), a customer registered with an `example.com` address and two saved addresses, the Spain market in euros, and the orders the record §5 lists. The guest is an invented name with an `example.com` address. No password, publishable key, token or webhook signing secret is recorded; the cart and order IDs in the notes are this lane's.

**Size.** 11.4 MB in 441 files: 155 screen captures, 59 comparison images and 4 email captures, with 222 JSON notes and results.
