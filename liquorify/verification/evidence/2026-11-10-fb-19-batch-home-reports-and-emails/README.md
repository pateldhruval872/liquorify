# FB-19 batch 11, home figures, reports and emails: evidence

The captures, comparisons, flow checks, emails and backend results behind the [verification record](../../2026-11-10-fb-19-batch-home-reports-and-emails.md). They come from the scripts in `packages/liquorify-storybook/fidelity/`: `screens-batch-11.spec.ts` and `compare-batch-11.spec.ts`, with the roles `staff.ts` adds; `fl-22.spec.ts`, which also checks the home page's figures and the operations counts; and `fl-18.spec.ts`. The emails gem's test app is started by `emails-stack.config.ts`.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | #89, branch `claude/project-thread-vptx49`, from `main` at `05b7c95b`; the scripts are `e3692b9b` |
| Running screens and Spree's specs | Spree's code at `05b7c95b`; the pull request does not change it. The built admin dashboard against the dashboard browser tests' own Rails server and fixtures (the browser-test server), and against the emails gem's test app, given Spree's seeds and sample data, with its mail written to a folder |
| The storefront | `b3202e8`, its `main`, on its development server, and built for production for SF-DEV-01's not-found state |
| Browser | The pinned Playwright 1.64.1 image. Captures at 1280 by 960 pixels, and 390 by 844 for the phone capture; a page captured whole grows the window to the page's height. Captures follow the system's light or dark setting |

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. All 352 were checked pixel for pixel against their PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The browser-test server shows the browser tests' data plus the sample customers, orders, a saved report ("Fidelity weekly sales") and the seven roles the scripts add through the Admin API; the emails gem's test app shows Spree's seeds and sample data. Every address the scripts add uses `example.com`. Each capture's store is written as `<store>`, the test servers' addresses as `<store-url>` and `<site>`, and the reset link's token in the three sent password reset emails and the logo's signed storage address in the six sent emails as `…`. No key or token appears.

**Fonts.** The email previews ask Google's font service for their fonts, which this session's network blocks; each capture that drew one lists the blocked requests under `outside` (4 or 8 each, 44 captures), and the previews show fallback fonts. Every other capture left the local servers for nothing.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role, the server, the theme, the path, the window's size, whether the page was captured whole, how a request was answered or held to reach the state (`intercepted`), whether the page settled (every capture but the loading states and the storefront's, which do not wait for it), and every request blocked because it would have left the local servers (`outside`) |
