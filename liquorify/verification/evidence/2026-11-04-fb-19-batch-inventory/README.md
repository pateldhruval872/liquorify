# FB-19 batch 6, inventory: evidence

The captures, comparisons and backend results behind the [verification record](../../2026-11-04-fb-19-batch-inventory.md). They come from the scripts in `packages/liquorify-storybook/fidelity/` (`screens-batch-6.spec.ts` and `compare-batch-6.spec.ts`, with the data `inventory.ts` and `staff.ts` add, and `g-78-stock-hold.spec.ts`) and from Spree's own specs. A successful run of the scripts only shows that each state could be reached and captured. Whether each story matches its screen is a judgement made from the images and styles here, recorded in the verification record.

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The screens show the browser tests' data, their two warehouses and their product, plus the products, suppliers, stock transfers, purchase orders, deliveries, roles and teammates the scripts add through the Admin API (record §1). Every name and reference the scripts add starts with "Fidelity", and teammates use `example.com` addresses. Each capture's store is written as `<store>` in its notes. **No key, token or password is recorded,** and no capture shows one.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role and permissions, the theme, the revision, the path, the window's size, how a request was answered or held to reach the state (`intercepted`), whether the page settled, and every request blocked because it would have left the local servers (`outside`, empty in all 264). The 8 notes of the four loading states record that the page did not settle, since a request is held open |
| `comparison/<case>/` | `<theme>-side-by-side.webp`: the running screen on the left and the story on the right; `<theme>-styles.json`: the computed styles of every distinct element on both sides, how many elements were compared, those found on one side only, and every style that differs |
| `stock-hold/<width>/` | G-78's check at the storefront's two widths, `desktop` and `phone`: seven captures named by step, and `answers.json`, with the stock level after each step, what each page said, the Store API's answers to the three shoppers' cart requests and to the product while it was held, and both revisions |
| `backend/` | `api-specs.json` and `core-specs.json`: every example of Spree's specs for the batch's endpoints, models and workflows, with its file, line, description and result |
