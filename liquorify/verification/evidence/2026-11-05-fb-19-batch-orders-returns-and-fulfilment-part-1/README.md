# FB-19 batch 8, orders, returns and fulfilment, part 1: evidence

The captures, comparisons, settings checks, emails and backend results behind the [verification record](../../2026-11-05-fb-19-batch-orders-returns-and-fulfilment-part-1.md). They come from the scripts in `packages/liquorify-storybook/fidelity/` (`screens-batch-8.spec.ts` and `compare-batch-8.spec.ts`, with the data `orders.ts` and `staff.ts` add; `orders-settings.spec.ts`, `digital-delivery.spec.ts`, `sd-31-gift-card.spec.ts` and `payment-link.spec.ts`; and `order-emails.rb` with `order-emails.spec.ts`) and from Spree's own specs. A successful run of the scripts only shows that each state could be reached and captured. Whether each story matches its screen is a judgement made from the images and styles here, recorded in the verification record.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | The pull request the verification record names, branch `claude/project-thread-fjhoj0`. The captures, comparison, settings checks and email captures ran from the branch's working tree on `08bca2e2`, and their notes name it |
| Running screens and Spree's specs | Spree's code at `08bca2e2`, the revision the work item names, the same as at `46c99cb7`, where the branch starts; the pull request does not change it. The built admin dashboard against the dashboard browser tests' own Rails server and fixtures |
| The storefront | `ba6ddcd`, its `main`, built for production and run against the same browser-test server, for the payment link and EM-SF-02 |
| Browser | The pinned Playwright 1.64.1 image. Captures at 1280 by 960 pixels, and 390 by 844 for the one phone capture; an order page captured whole grows the window to the page's height. Comparisons at 1280 by 800, or taller where a case names it. Emails at 390 and 1280 pixels wide. Captures follow the system's light or dark setting; none stores a choice of theme |

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The screens show the browser tests' data, their products and customers, plus the orders, payments, discounts, fees, gift cards, store credit, reasons, roles and teammates the scripts add through the Admin API (record §1). Every name and reference the scripts add starts with "Fidelity", and customers and teammates use `example.com` addresses. Each capture's store is written as `<store>` in its notes. **No key, token or password is recorded,** and no capture shows one: order and download tokens are written `<token>` or `<order token>`, and local addresses `<site>` or `<storefront>`.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role, the theme, the revision, the path, the window's size, whether the page was captured whole, how a request was answered or held to reach the state (`intercepted`), whether the page settled, every request blocked because it would have left the local servers (`outside`, empty in all 262), and the order's customer. The 4 notes of the two loading states record that the page did not settle, since a request is held open |
| `comparison/<case>/` | `<theme>-side-by-side.webp`: the running screen on the left and the story on the right; `<theme>-styles.json`: the computed styles of every distinct element on both sides, how many elements were compared, those found on one side only, and every style that differs |
| `settings/<setting>/` | Each setting saved on its screen and seen on an order, captures named by step, with `answers.json`: what the server answered for the setting and the order |
| `digital-delivery/` | A file added on the digital product's page and the order's Downloads card before and after its link was opened, with `saved.json` and `answers.json` |
| `sd-31/` | SD-31's five steps through the dashboard, with `answers.json`: the gift card as the Admin API read it after each step, and the server's answer to each apply |
| `payment-link/` | The payment link email's address and the storefront's checkout page opened with the draft's token and id, with `answers.json` |
| `emails/` | `<email>-390.webp` and `<email>-1280.webp` for each email, and `emails.json`: each Spree email's subject, parts and links |
| `backend/` | `api-specs.json`, `core-specs.json` and `email-specs.json`: every example of Spree's specs for the part's endpoints, models, workflows and mailers, with its file, line, description and result |
