# FB-19 batch 13 part 1, the operator's seller screens: evidence

The captures, comparisons, checks, emails and backend results behind the [verification record](../../2026-11-10-fb-19-batch-marketplace-part-1.md). They come from the scripts in `packages/liquorify-storybook/fidelity/`: `marketplace-seed.rb` and `marketplace.ts`, which make the marketplace on the browser-test server, with the roles `staff.ts` adds; `screens-batch-13.spec.ts` and `compare-batch-13.spec.ts`; `marketplace-checks.spec.ts`; and `marketplace-emails.rb`, with `order-emails.spec.ts` capturing the emails.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | #98, branch `claude/project-thread-tcfmf8`, from `main` at `0950e2de`; the captures were taken at `6b163aad` with the scripts of `7b11756c`, the comparison at `495e704f`, the checks at `44363bfb` and the emails at `bbe95678` |
| Running screens and Spree's specs | Spree's code at `0950e2de`; the pull request does not change it. The built admin dashboard against the dashboard browser tests' own Rails server and fixtures (the browser-test server). The emails were rendered on the emails gem's test app against a copy of that server's database |
| Browser | The pinned Playwright 1.64.1 image. Captures at 1280 by 960 pixels, and 390 by 844 for the phone captures; a page captured whole grows the window to the page's height |

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. All 351 were checked pixel for pixel against their PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The browser-test server shows the browser tests' data plus the eight sellers, their products, ledger and orders, two commission rates and the five roles the scripts add through the Admin, Seller and Store APIs. Every person, seller and address the scripts add is invented and uses `example.com`. Each capture's store is written as `<store>` and the test servers' addresses as `<site>`; the invitation link's token in EM-S-03 is `<token>`. The checks' answers mask every field named like a token, secret or password. No key or token appears.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role, the server, the theme, the path, the window's size, whether the page was captured whole, how a request was answered or held to reach the state (`intercepted`), whether the page settled, and every request blocked because it would have left the local servers (`outside`, empty for every capture) |
| `comparison/<case>/` | `<theme>-side-by-side.webp`: the running screen on the left and the story on the right; `<theme>-styles.json`: the computed styles of every distinct element on both sides, how many were compared, those found on one side only, and every style that differs |
| `checks/<check>/` | The captures each check of `marketplace-checks.spec.ts` took, numbered in order, and `answers.json` with what the Admin, Seller and Store APIs answered at each step. `requirements/first-run.txt` and `mark-paid/first-run.txt` say what the first run of those two checks did and read; `ranking-and-report/report-query-month-to-date.json` is the seller payouts report's query for this month |
| `emails/` | Each email's HTML part as `<email ID>.html`, captured at 390 and 1280 pixels, and `emails.json` with each subject, part and link, and what each sent check delivered, with recipients counted |
| `backend/` | Spree's spec results as RSpec JSON: `api-specs.json` (359 examples), `core-specs.json` (559) and `email-specs.json` (55) |
| `screens-run.txt`, `comparison-run.txt` | The logs of the capture and comparison runs |
