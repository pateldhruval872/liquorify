# FB-19 batch 7, payments, delivery and tax settings: evidence

The captures, comparisons and backend results behind the [verification record](../../2026-11-04-fb-19-batch-payments-delivery-and-tax.md). They come from the scripts in `packages/liquorify-storybook/fidelity/` (`screens-batch-7.spec.ts` and `compare-batch-7.spec.ts`, with the data `payments-delivery.ts` and `staff.ts` add) and from Spree's own specs.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | Pull request [#41](https://github.com/pateldhruval872/liquorify/pull/41). The captures ran from the stories and scripts `eb912b31` commits, with the scripts' later changes in `payments-delivery.ts` and `screens-batch-7.spec.ts`, which the records commit adds. The comparison ran with the corrected stories `0d4b3c1d` commits (record §4.2) |
| Running screens and Spree's specs | Spree's code at `main` `87a2ea80`, which is the same as at `5794da6a`, the revision the work item names, and which the pull request does not change: the built admin dashboard against the dashboard browser tests' own Rails server and fixtures |
| Browser | The pinned Playwright 1.64.1 image. Captures at 1280 by 960 pixels, and 390 by 844 for the two phone states of DA-SET-17; comparisons at 1280 by 800, and taller windows for the sheets and the long sections (record §4). Captures follow the system's light or dark setting; none stores a choice of theme |

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The screens show the browser tests' data, plus the payment methods, tax categories and rates, delivery profiles, zones, methods, package types, roles and teammates the scripts add through the Admin API (record §1). Teammates use `example.com` addresses. Each capture's store is written as `<store>` in its note.

**Secrets.** The test gateway's secret setting is a value the capture script makes at each run and never writes down. It is painted out in every capture that shows its field, and the note says so under `masked`. The comparison paints out the same field on both sides. The test gateway's public key field shows `PUBLICKEY123`, the value Spree's test gateway ships as its default, which is not a key. No other key, token or password is shown.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role and its permissions, the theme, the revision, the path, the window's size, how a request was answered or held to reach the state (`intercepted`), what was painted out (`masked`), whether the page settled, and any request blocked because it would have left the local servers (`outside`, empty in all 180) |
| `comparison/<case>/` | `<theme>-side-by-side.webp`: the running screen on the left and the story on the right; `<theme>-styles.json`: the computed styles of every distinct element on both sides, the elements compared, those found on one side only, and every style that differs |
| `backend/` | `api-specs.json` and `core-specs.json`: every example of Spree's specs for the batch's endpoints and models, with its file, line, description and result |

Variants are `admin`, `admin-phone` (390 by 844), `deliveryViewer` (read on `settings`, `delivery_methods` and `package_types`), `deliveryEditor` (read on `settings`, write on `delivery_methods` and `package_types`) and `orderManager` (the order manager template). The record §3.1 gives each role's permission keys.
