# FB-19 storefront shop batch, part 1: evidence

The captures, comparisons and results behind the [verification record](../../2026-10-26-fb-19-batch-storefront-shop-part-1.md). They come from the storefront's scripts in `visual/fidelity/` (`shop-screens.spec.ts` and `compare.spec.ts`), from Spree's own specs and from the storefront's own browser tests. A successful run of the scripts only shows that each state could be reached and captured. Whether each story matches its screen is the owner's judgement from these files.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | Storefront draft pull request [#20](https://github.com/pateldhruval872/liquorify-storefront/pull/20) at `da06743` |
| Running screens and the browser tests | The storefront at `main` `321fa1c`, which #20 does not change, built for production, against lane A's own browser-test Rails server at backend `d6a0fb8` |
| Spree's specs | Spree's code at `d6a0fb8`, the same as `main` `afd97cd` |
| Browser | The storefront's pinned Playwright 1.60.0 image, at 390 and 1280 pixels wide, with the fonts served offline |

**Three storefront set-ups.** `standard`, the storefront as built for production; `wholesale`, the same storefront built with a wholesale channel, for the wholesale section and links; and `proxied`, the standard storefront reaching the backend through a small proxy in the capture script, which held or failed the product list for the loading and error states, with a third market whose currency no product has a price in. The record §2.1 says which state used which.

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image, 126 in all, was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in the storefront's `visual/__screenshots__/`.

**Data.** The screens show Spree's sample catalog, loaded into lane A's own browser-test database with Spree's `spree:load_sample_data` task, plus what the record §2.1 lists, added through Spree's Admin and Store APIs. The customer was registered by the capture run with an `example.com` address. No password, token or key is recorded.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light-390.webp` and `<variant>-light-1280.webp`, and a JSON note for each: the screen, the state, the variant, the width, the storefront's revision, the path, what the browser observed that a picture cannot show (`observed`) and any note. A state the storefront shows at only one width has only that width |
| `comparison/<case>/` | `<width>-side-by-side.webp`: the running screen on the left and the story on the right; `<width>-styles.json`: the computed styles of every distinct element on both sides, the elements compared, those found on one side only, and every style that differs. `mobile` is 390 pixels and `desktop` 1280. A case shown at only one width on the storefront has only that width |
| `comparison/tokens.json` | The design tokens on the running storefront and in Storybook, counted, with each one that differs |
| `backend/` | `api-specs.json`: every example of Spree's Store API specs for the endpoints part 1's screens read, with its file, line, description and result |
| `flows/` | `storefront-browser-tests.json`: each of part 1's browser tests with its result, run locally |
