# FB-19 catalog and pricing batch, part 3: evidence

The captures, comparisons and backend results behind the [verification record](../../2026-11-04-fb-19-batch-catalog-and-pricing-part-3.md). They come from the scripts in `packages/liquorify-storybook/fidelity/` (`screens-catalog-3.spec.ts` and `compare-catalog-3.spec.ts`, with the data `loyalty.ts` and `staff.ts` add) and from Spree's own specs. A successful run of the scripts only shows that each state could be reached and captured. Whether each story matches its screen is a judgement made from these files.

**Revisions.**

| What | Revision |
|---|---|
| Stories and scripts | Pull request [#61](https://github.com/pateldhruval872/liquorify/pull/61). The captures ran from `4a05d9c8`, and five promotion states from `e040f9d1`: usage-limit-below-one, save-refused, action-removed-unsaved, saved-rule-products-unreadable and saved-rule-customers-unreadable (record §2.1). The comparison ran from `e040f9d1`. Between the two, only the capture and comparison scripts and the records changed |
| Running screens and Spree's specs | Spree's code as `main` has it at `ffc9f5e0`, whose last change to Spree's code is `bbf401c4`; the pull request does not change it. The built admin dashboard against the dashboard browser tests' own Rails server and fixtures, with Spree's sample catalog loaded into its database |
| Browser | The pinned Playwright 1.64.1 image. Captures at 1280 by 960 pixels, and 390 by 844 for the phone states; comparisons at 1280 by 800, or 1280 by 960 where a case names it. Captures follow the system's light or dark setting; none stores a choice of theme |

**Image format.** Every image here is lossless WebP, converted from the PNG each script wrote. Every converted image was checked pixel for pixel against its PNG, and none differs. The reference images the visual check compares against stay PNG, in `packages/liquorify-storybook/visual/__screenshots__/`.

**Data.** The screens show the browser tests' data and Spree's sample catalog, plus the promotions, coupon codes, gift cards, store credits, orders, roles and teammates the scripts add through the Admin API (record §1). Shoppers and teammates use `example.com` addresses. Each capture's store is written as `<store>` in its notes. **No key, token or password is recorded,** and no capture shows a key. The comparison's key mask hides any code drawn in a card on both sides; no part 3 case draws a key.

## Folders

| Folder | Holds |
|---|---|
| `screens/<screen ID>/<state>/` | `<variant>-light.webp` and `<variant>-dark.webp` for each variant, and `<variant>-<theme>.json`: the screen, the state, the variant's role, the theme, the revision, the path, the window's size, how a request was answered or held to reach the state (`intercepted`), whether the page settled, every request blocked because it would have left the local servers (`outside`, empty in all 326), and every request the server refused (`refused`) |
| `comparison/<case>/` | `<theme>-side-by-side.webp`: the running screen on the left and the story on the right; `<theme>-styles.json`: the computed styles of every distinct element on both sides, the elements compared, those found on one side only, and every style that differs |
| `backend/` | `api-specs.json` and `core-specs.json`: every example of Spree's specs for part 3's endpoints, models and workflows, with its file, line, description and result; `api-checks.json`: the Admin API checks for G-14, a duplicate coupon code and an erased shopper's credit (record §4, B13 and B18) |

- **orderManager** is a teammate with Spree's order manager template's role.
- **merchandiser** is a teammate with Spree's merchandiser template's role.
