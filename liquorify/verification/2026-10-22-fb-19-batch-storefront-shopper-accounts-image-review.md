# FB-19 storefront shopper accounts batch, reference images for the owner's review

This list holds every reference image the batch commits, by inventory ID ([LIQ-009](../LIQ-009-spree-component-and-token-inventory.md)), so the owner can accept or reject each one. On 2026-10-23, after merging #12 and storefront #18, the owner accepted the batch as a whole, these images included ([record](2026-10-23-fb-19-batch-storefront-shopper-accounts-merge.md)). The Owner column still reads NOT_RUN for each image, because that answer covered the batch as a whole, not each image.

**What to look at.** Each link opens the image as committed on storefront pull request [#18](https://github.com/pateldhruval872/liquorify-storefront/pull/18), at its final commit `2e5f119`; the pull request's file list shows the same images. That commit's capture correction regenerated 112 of them with 8 pixels of room on each side, each identical inside to the image first committed at `49e1c37` (record, "Capture correction"). Each story has two: `mobile` at 390 pixels and `desktop` at 1280. The storefront shows no dark mode, so there is one theme. Every image was looked at before it was committed.

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on the running storefront, and the result is in the [verification record](2026-10-22-fb-19-batch-storefront-shopper-accounts.md) §4. "Compared within" means the component was compared as part of a larger one that holds it. Images and computed styles are in the [evidence index](evidence/2026-10-22-fb-19-batch-storefront-shopper-accounts/README.md). The comparison is diagnostic: it informs the owner's review and does not replace it.
- **Seen in a capture:** the state appears in a running-screen capture, linked here at 1280 pixels, but the script did not put the story beside it. The owner can look at both.
- **Not compared; checked against its source:** no running screen showed that state with the test data, so it was checked against the component's source only. Where a reason is known, it is given.

**How a decision is recorded.** The owner accepts or rejects in the pull request, row by row or as a whole. An image rejected is fixed in its story, its fixtures or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).

**Counts.** 103 stories, 206 images. 21 compared on a running screen, two of them within another component; 33 seen in a capture; and 49 checked against their source only.
