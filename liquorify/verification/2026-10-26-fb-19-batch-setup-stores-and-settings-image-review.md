# FB-19 setup, stores and settings batch, reference images for the owner's review

This list holds every reference image the batch commits, by inventory ID ([LIQ-009](../LIQ-009-spree-component-and-token-inventory.md)), so the owner can accept or reject each one. Every row reads PENDING until the owner reviews the batch.

**What to look at.** Each link opens the image as committed on the pull request's branch; the pull request's file list shows the same images. Every image was looked at in light and dark before it was committed. Stories use invented values; the storefront sheet's key is a plain sample that does not look like one. The settings page's three phone stories are drawn at 390 by 844 pixels, so their images are named `phone-light` and `phone-dark`.

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on Spree's running admin dashboard, and the result is in the [verification record](2026-10-26-fb-19-batch-setup-stores-and-settings.md) §4. Images and computed styles are in the [evidence index](evidence/2026-10-26-fb-19-batch-setup-stores-and-settings/README.md). The comparison is diagnostic: it informs the owner's review and does not replace it.
- **Seen in a capture:** the state appears in a running-screen capture, linked here, but the script did not put the story beside it. The owner can look at both.
- **Not compared; checked against its source:** no running screen showed that state with the browser-test data, so it was checked against the component's source only. Where a reason is known, it is given.

**How a decision is recorded.** The owner accepts or rejects in the pull request, row by row or as a whole. An image rejected is fixed in its story, its providers or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).

**Counts.** 150 stories, 300 images. 29 compared on a running screen, 51 seen in a capture, and 70 checked against their source only.
