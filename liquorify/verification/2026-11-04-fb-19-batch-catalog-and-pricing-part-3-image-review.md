# FB-19 catalog and pricing batch, part 3, reference images for review

This list holds every reference image part 3 commits, by inventory ID ([LIQ-009](../LIQ-009-spree-component-and-token-inventory.md)), so each can be accepted or rejected, and the earlier batches' stories that part 3's running screens compare. On 2026-11-04 part 3 was accepted by delegated acceptance, under the owner's delegation of 2026-11-04 ([record](2026-11-04-delegated-acceptance-and-merging.md)), at #NN's final commit, by Claude in the thread "Build catalog part 3: promotions and loyalty" ([verification record §12](2026-11-04-fb-19-batch-catalog-and-pricing-part-3.md#12-acceptance)). The owner did not review these images. The Acceptance column reads DELEGATED ACCEPTANCE for each.

**What to look at.** Each link opens the image beside this list, in the revision being read, and the pull request's file list shows the same images. Every image was looked at in light and dark before it was committed. Stories use invented shoppers, codes and amounts; the running screens show the browser tests' data, Spree's sample catalog and the records part 3 added through the Admin API. Some story names hold a comma of their own, such as "New promotion, a coupon code by default".

**What the Running screen column means.**
- **Compared:** the story was put beside the same component on Spree's running admin dashboard, and the result is in the [verification record](2026-11-04-fb-19-batch-catalog-and-pricing-part-3.md) §5. Images and computed styles are in the [evidence index](evidence/2026-11-04-fb-19-batch-catalog-and-pricing-part-3/README.md). The comparison is diagnostic: it informs the review and does not decide it.
- **Seen in a capture:** the state appears in a running-screen capture, linked here, but the script did not put the story beside it. A capture of a role other than the admin names the role.
- **Not compared; checked against its source:** no running screen showed that state with the browser-test data, or the script could not reach it there, so it was checked against the component's source only. Where a reason is known, it is given. These stories are G-81 (record §8).

**How a decision is recorded.** An image is accepted or rejected in the pull request, row by row or as a whole. An image rejected is fixed in its story, its providers or its mocks, never by changing the component ([LIQ-010 §12.1](../LIQ-010-design-system-reproduction-architecture.md#121-each-batch)).
